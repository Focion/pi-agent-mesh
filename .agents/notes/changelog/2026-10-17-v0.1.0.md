## 概要

首个本地就绪版本 **0.1.0**（规范面 v1.0.0 已定稿）。`@pi/agent-mesh` 是构建在 pi SDK 之上的多持久 Agent 消息传递与共享状态层：P0 双账号互发、P1 群广播唤醒、topic、request-应答、queue、共享空间、observer.replay 与 sameHost 同机多进程均已闭合；模型与运行时统一由 Mesh 配置（`createMesh({ llm, runtime })`），使用者不需要安装、登录或维护 pi 配置。

配套 `verify:local`（G01–G07）与 `verify:package`（G08–G09）两套可机器判定的本地门禁，覆盖分层、类型、测试、覆盖率、真实 tarball 消费者（ESM/CJS × 有无 pi）与交付一致性。

## 破坏性变更

| 变更 | 影响范围 | 迁移方式 |
| --- | --- | --- |
| Node engine `>=20` → `>=22.19.0` | 所有调用方 | 升级 Node 到 22.19.0 及以上（本机验证 24.19.0） |
| pi SDK 由 optional peer → `@earendil-works/pi-coding-agent@^1.1.0` 直接依赖 | 安装形态 | 无需手动安装 pi；包在运行时经 `loadPiSdk()` 惰性加载，core-only 使用者不加载 pi |
| Presence 状态由五值 → 七值：`available/busy/dnd/away/online/idle/offline` | 读 `presence_changed` / `setPresence` 的方 | `online`/`idle` 为 stream 派生态，`available`/`away` 为 legacy 别名 |
| 工具 `mesh_shared_put`/`mesh_shared_list` 参数改 opts 形态（`append`/`maxLen`/`sinceVersion`/`limit`） | 调用 shared 工具的宿主 | 按 C08 的 API 快照更新签名；`put` 的 append 行为显式分派，不再静默覆盖 |
| `historyVisibility` 枚举收敛为 `none/since_join/full`（原 `sinceJoin`） | 读规范/自定义策略的方 | 旧拼写 `sinceJoin` 不再有效 |

## 新增

- **Mesh 统一 LLM 配置**（W00）：`createMesh({ llm: { model, apiKeyEnv, providers? }, runtime: { builtinTools, … } })` 内部完成完全隔离的 pi 装配，不读 `~/.pi`、不启用内建工具；高级路径仍可经 `policies.sessionFactory: createAssembledSessionFactory({ stateDir, llm, runtime })` 自行驱动。
- **投递/对话能力**：P1 群广播唤醒与原文预算、topic 订阅 fanout、request-应答（含环检测与 late 应答）、queue 认领/requeue/死信、共享空间（CAS + ACL + 通知 read 过滤）、observer 观测面（trace/inboxOf/counters/checkInvariants/replay）。
- **sameHost 多进程**（§19）：同机多进程经共享 SQLite 与端点锁，跨进程投递与恢复闭环。
- **D03 权威恢复**：`reconcileDelivered` 对 delivered 行按真实 pi session 逐条双向核对、幂等应用；`maxHistoryOnJoin`、P2 注入确认、CATCHUP 持久化等收口。
- **共享空间安全合同**（§4.2）：put 按旧 ACL 授权、改 ACL/删除需 admin、并发 CAS 闭合、归档禁写、私有通知按 read 过滤且 silent。
- **观测/事件/计数**：`DeliveryTrace.note/redeliverReason`、事件统一携带端点元信息、三计数器（blind_write/claim_timeout/queue_cleared_detected）与 fold/busy 单位对齐。

## 修复

- 闭合 41 项实现差距（N01–N05、I01–I35、D03）：邮箱周期清扫、FTS 可关、写者归属、跨主投递层级一致、字节预算、claim 校验、Shared CAS、事件漏发、trace 可解释性等。
- 版本三重（`LIBRARY_VERSION`/`package.json`/`package-lock`）统一为 `0.1.0`；规范 H03 命名收敛（枚举、事件字段对齐代码）。

## 升级步骤

1. 确认 Node ≥22.19.0：`node -v`。
2. 安装：`npm install`（pi 与 better-sqlite3 由包声明直接交付）。
3. 构建：`npm run build`；如需本地包验证：`npm run verify:local -- --all` 与 `npm run verify:package`。
4. 若从早期形态迁移：`historyVisibility` 旧值 `sinceJoin` 改为 `since_join`；shared 工具调用改 opts 签名；`setPresence` 目标状态改用七值枚举。

## 回滚方式

本版未引入数据破坏性迁移（`000_init.sql` 只读基线不动，增量迁移 `001–004` 仅追加列）；回退到旧 tarball 后重新打开本地库即可，无需重建数据。不可逆部分：`claim_owner`/`delivery_decision` 新增列会保留，旧包读取新库不受影响（新列对旧读透明）。
