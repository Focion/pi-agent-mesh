## 概要

**pi SDK 平台基线 1.4.0 → 1.5.0**：`@earendil-works/pi-durable` / `pi-ai` / `chord` 三包精确锁定 1.5.0，并显式新增 `@earendil-works/pi-schema@1.5.0` 直接依赖声明；mesh 包版本保持 **0.2.0**（本次变更未提交、未推送、未发布）。核心变化：条目镜像与轮次边界由 watch 差分改为 `harness.observeCommits()` 提交观察（串行 drain + `root.entries` 分页基线），并引入「先 delivered 后 consumed」的确认完成屏障与 `turnEnd` 的 `eligibleEntryIds` 消费边界。**DDL 不变**，无新迁移；规范升 1.0.4（变更见规范附录 L.4）。

## 破坏性变更

| 变更 | 影响范围 | 迁移方式 |
| --- | --- | --- |
| **pi 依赖精确锁定 1.5.0** | 所有调用方 | `npm install` 即得（lock 文件已更新）；`pi-schema@1.5.0` 为新增直接依赖声明。无 1.4/1.5 双 SDK 兼容分支，factory 与契约测试一律按 1.5 |
| **`StreamPort` 接口收为 10 个方法：`hasEntries` 删除、`dispose` 退出接口** | 自定义 `StreamPort` 实现者 | `hasEntries` 已无实现与调用方（崩溃恢复只走 `submissionStatus` 对账，§7.9⑤）；`dispose`（A21 强制卸载）保留为 durable 端口实现细节，`close()` 以鸭子类型调用——自定义端口可不实现，卸载仍走 `evict` |
| **`onEntry` 处理器签名放宽** | 自定义 `StreamPort` 实现者 | 处理器类型改为 `(e: PortEntryEvent) => void \| Promise<void>`，库把返回值当**确认完成屏障**（先 delivered 后 consumed，规范 §7.9⑥）。旧 `void` 处理器仍赋值兼容；包根装配必须透传 promise（库已处理；宿主自装配端口时不得吞掉——吞掉即屏障失效） |
| **`onTurnEnd` 事件增加 `eligibleEntryIds?`** | 自定义 `StreamPort` 实现者 | 事件载荷增加该轮边界内已纳入基线/entry 通知的 entry_id 快照；Mailbox 消费事务只选该集合内的 delivered 行。**不传该字段的端口保留原有全量消费行为**（不丢投递，只损失边界精度） |
| **continue 提交投影不支持** | 宿主 | pi 1.5 的 `continue` 型提交在 `submissionStatus` 显式报不支持（返回 null），不伪装成 input/write、不为 continue 提交新增条目 |

## 新增

- **`RuntimeConfig.progressPersistWithinMs`**（缺省 `0`）：pi 1.5 progress 落盘窗口，非负安全整数。缺省 0 保持与旧版相近的每-partial 持久化强度；宿主可显式放宽（如 `1000`）以降低写放大。

## 修复

- 条目镜像不再受 50/100 内存窗口限制（`observeCommits` + `root.entries` 分页基线）：窗口外条目不漏镜像，`seqInStream` 连续。
- busy→idle 与旧 run→新 run 边界按 `pi.live` 的 run 身份（inputs 集合）判定，轮次切换不漏 `turnEnd`、不误报。
- `harness.resume()` 移至端口 warm 末尾（观察器挂好、基线就绪之后）；warm 后半段失败回滚（摘除 stream、detach 观察器、释放单写者锁），该端点可重试热化。
- 观察器非正常终止（`session closed` 异常路径）走 `unavailable` + 降级通道（`onDegraded`），不再表现为正常热态。

## 升级步骤

1. 确认 Node ≥ 24：`node -v`。
2. 安装：`npm install`（lock 文件已更新为 1.5.0 精确版本）。
3. 构建：`npm run build`。
4. 部署前备份：
   - mesh SQLite（消息/投递/共享空间）——本次**无新迁移**、DDL 不变，备份是常规纪律；
   - **每个端点的 pi durable storage**——pi 1.5 会读取并可能改写 1.4 写入的存储（见「回滚方式」的不可逆部分）。
5. 若宿主实现了自定义 `StreamPort`：按「破坏性变更」表核对 `onEntry` / `onTurnEnd` 两个签名。
6. 验证：`npm test`（原 665 测试 + 新增回归全绿）、`npm run pack`、`npm run verify:package`。

## 回滚方式

- **回退依赖**：`package.json` 四包改回 1.4.0（删除 `pi-schema`），`npm install` 重装；代码同步回退（本次变更未提交——见 git 工作区改动）。
- **不可逆部分**：pi 1.5 运行过的 durable storage 可能已被 1.5 改写，**不能仅靠回退依赖与锁文件解决**；需恢复升级前各端点 durable storage 的副本。mesh 自己的 SQLite 无 schema 变化，但其投递状态由 1.5 语义推进过，一并从备份恢复最稳妥。
- 本次变更**未提交、未推送、未发布**：`version` 保持 0.2.0，无 tarball 发布动作。
