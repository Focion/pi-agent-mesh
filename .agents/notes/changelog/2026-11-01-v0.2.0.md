## 概要

**0.2.0** 从 pi-coding-agent 迁移到 pi-durable（规范面升为 1.0.3）。核心变化：执行体从 `AgentSession` + JSONL session 文件切换为 `Harness` + 事务化 storage；投递判据从「猜 entry 何时落地」切换到「submission 状态投影为权威」；三套为补偿 coding-agent 缺陷而存在的机制（handoff 超时回退、entry 差分镜像、beforeClearQueue/I22 协议）全部退役。同时闭合了 60 项审计缺陷（A01–A60）和三处规范裁决（R1、R2、R4）。

## 破坏性变更

以下四条合并为一条公告，迁移说明见下方「升级步骤」。

| 变更 | 影响范围 | 迁移方式 |
| --- | --- | --- |
| **Node engine `>=24.0.0`** | 所有调用方 | 升级 Node 到 24.x；pi-durable 的 `node:sqlite` 要求 ≥22.5，chord 要求 ≥23.10.0，综合取 ≥24 |
| **`piSessionId` → `runtimeRef`** | 读端点标识的方：Observer 流读取面、MeshHost API、工具面 | `runtimeRef` 是 `{storagePath, conversationId}` 的 JSON 包装；旧 DB 中的 `pi_session_id` 经 `migrations/005_runtime_ref.sql` 原样迁入 `runtime_ref` 列 |
| **`RuntimeConfig.resources` 废弃** | 配置 `resources` 的宿主 | 置 `true` 时抛配置错误（durable 不提供 DefaultResourceLoader 对等物）；skills/prompts/contextFiles/MCP 暂不支持——见下方「能力缺口」 |
| **coding-agent session 不平移** | 有 v0.1.0 历史 session 的部署 | pi-coding-agent 的 JSONL session 文件不是 pi-durable 的 storage 格式；历史会话需在升级前归档或在新部署上重建；mesh 自己的 SQLite 数据（消息/投递/共享空间）不受影响，仍由 better-sqlite3 直接读写 |

## 新增

- **durable 后端**（迁 3–4）：`src/pi/durable-port.ts` 以 pi-durable `submit`/`watch`/`entries` 重写 StreamPort 11 方法；`deliver` 返回 `SubmissionHandle {submissionId, status, entryId?}`；新增 `submissionStatus`（按 id 精确读权威投影）与 `dispose`（强制卸载全部流，A21）；`durable-runtime.ts` 经 pi-ai `createModels`/`createProvider` + `InMemoryCredentialStore` 显式密钥 seed。
- **submission 驱动的投递语义**（迁 8）：`markDelivered` 依 `res.status ∈ {placed, done}` 推进；`consumed` 按 input/write 两型分流（input: done 即 consumed，write: 下一 turn_end）；崩溃恢复 `reconcileDelivered` 改为 `submissionStatus` 按 id 精确读（A03/A04）。
- **补偿机制退役**（迁 9）：handoff 超时回退（F5）、entry 差分镜像（F2）、`beforeClearQueue`/I22（F3）、`inFlightCount` 自持计数（F3）全部删除；背压改用 `port.status().inFlight`；`handoffTimeoutMs`/`handoffAt` 字段完全移除。
- **端点标识重构**（迁 5）：`piSessionId` → `runtimeRef`（`{storagePath, conversationId}` 的 JSON 包装）；`migrations/005_runtime_ref.sql` 包含 `submission_id`/`attempt` 列与 `mesh_stream_entries` 主键 `(runtime_ref, entry_id)`；`RuntimeRef` 公开导出 + `decodeRuntimeRef`/`encodeRuntimeRef` 帮助函数。
- **审计修复 60 项**（步骤 1–8）：覆盖投递（A01/A02/A06/A08/A09/A10）、存储/并发（A11/A14–A20）、生命周期（A22/A25–A27）、安全（A30/A32–A35/A40/A42/A44）——含 A08/A09 验收测试、A18 多进程迁移并发、A30 定向可见性过滤、A32 建群准入夹紧、A33 outbox 回源验签等。
- **实例锁强化**（A12/A13）：`lock.ts` 记录 `mode`（single/multi 互斥）、`reclaim`（rename 抢占 + 判活 + link 原子放回）、release/refresh 前校验持有者。
- **规范升 1.0.3**（迁 10）：§2 基线、§2.3 F1–F5 退役、§2.4 StreamPort 11 方法、§7 投递判据、I22 退役/I23 更新、L.4 完整变更记录。
- **新计数器**：`routed_retry`（sweep routed 滞留重投次数）。

## 修复

- A01：多端点反查按 `endpoint_id` 定位，重投不扩行。
- A02：fanout 逐收件人 try/catch + sweep ①.5 routed 滞留重投 + 启动 `reconcileRouted`。
- A11：outbox 状态回写带 CAS，投递前复核行状态。
- A15：FTS 写回退，requeue 先 route 成功再撤原行。
- A20：`folded_to_seq` 由 fold 路径落盘（权威字段，恢复不重算）；SCHEMA_VERSION 未知迁移戳拒绝启动。
- A22：能力校验前移抢锁前 + 装配段 try/catch 回滚。
- A26：全写入口 `assertOpen()` + close 等在途 sweep + `void` 调用补 catch。
- A25：tsup `splitting: true` 统一跨入口错误类身份 + 根入口值导出 `MeshRejectError`。
- A30：`history` 与 `injectJoinHistory` 按 `to_accounts` 过滤定向消息（R4 裁决）。
- C5：`requeueForRedelivery` 的 guarded UPDATE 按 `res.changes > 0` 门控后续操作，终态行不可复活。

## 能力缺口（相对 v0.1.0）

以下 pi-coding-agent 能力在 pi-durable 中没有直接对等物，暂不支持：

| 缺口 | 影响 | 替代路径 |
| --- | --- | --- |
| `resources`（skills/prompts/contextFiles/MCP） | 依赖这些的宿主无法升级 | `resources` 置 `true` 时显式抛配置错误，不静默无效 |
| `DefaultResourceLoader` | 内置 skill 与 prompt 模板不可用 | 宿主自行管理 skill 文件并通过 `RuntimeConfig` 加载 |
| 第三方 extensions | coding-agent 扩展接口不对应 durable 的 `Extension` | `RuntimeConfig.extensions` 字段保留但不生效 |

## 升级步骤

1. 确认 Node ≥24：`node -v`。
2. 安装：`npm install`（pi-durable 1.3.0 / pi-ai 1.3.0 / chord 1.3.0 由包声明交付，coding-agent 不再安装）。
3. 构建：`npm run build`。
4. 若从 v0.1.0 升级：
   - **历史 session 不平移**：v0.1.0 的 pi-coding-agent JSONL session 文件无法在 v0.2.0 上恢复。mesh 的 SQLite 数据（消息/投递/共享空间）在库升级时经迁移脚本原样保留，但与之关联的 pi session 需在新部署上重建。
   - **端点标识改名**：引用了 `piSessionId` 字段的代码改为 `runtimeRef`（`{storagePath, conversationId}` 的 JSON 包装）。读 `mesh_endpoints.pi_session_id` 的 SQL 改为 `runtime_ref`。
   - **`handoffTimeoutMs`/`handoffAt`**：已从代码中完全移除。构建配置中的 `handoffTimeoutMs` 字段需删除（不再生效）；`DeliveryTrace.handoffAt` 不再输出。投递由 submission 状态投影驱动。
   - **`beforeClearQueue` 已移除**：若宿主曾调用 `host.beforeClearQueue(endpointId)`，删除该调用——durable 的 submission 模型无需此协议。

## 回滚方式

恢复 `package.json` 的 `version` 到 `0.1.0`，重新安装 `@earendil-works/pi-coding-agent@^1.1.0`，回退 `node_modules`。**注意**：升级后运行过的 DB 已应用 `migrations/005_runtime_ref.sql`（列改名 + 新列），回滚后 DB schema 与 v0.1.0 代码不兼容，需从备份恢复或重建。
