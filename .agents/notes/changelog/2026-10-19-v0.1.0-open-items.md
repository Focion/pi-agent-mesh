## 概要

0.1.0 关闭之后仍悬空的 D1–D6 / T1–T9 收口（对应 `notes/archive/2026-10-19-post-0.1.0-open-items-plan.md`）。对使用方有感知的是一处**破坏性变更**（D2：移除 `MeshEvent`/`MeshEventMeta`）与一批**纯新增**（T5：根入口补齐常量 re-export），另有两条语义修正（T2/T3）影响可观测行为。规范同步升级到 1.0.2。

## 破坏性变更

| 变更 | 影响范围 | 迁移方式 |
| --- | --- | --- |
| 从包根公共面移除 `MeshEvent`（判别联合）与 `MeshEventMeta` 两个类型 | `import type { MeshEvent, MeshEventMeta } from "@pi/agent-mesh"` 的使用方 | 事件订阅改为按事件名取具体载荷：`on("message_delivered", (ev: MeshEvents["message_delivered"]) => …)`，或类型换成 `keyof MeshEvents` 的穷尽 `switch`。这两个类型本就没有生产路径（总线只派发 `MeshEvents[K]`），移除不改变运行时行为 |

## 新增

- **根入口补齐常量 re-export（T5）**：`REJECT_CODES` / `PARK_REASONS` / `DROP_REASONS` / `TOOL_ERROR_CODES` / `REGISTERED_COUNTERS` / `MESH_TOOL_NAMES` 现在能直接从 `@pi/agent-mesh` 导入（此前只在 `@pi/agent-mesh/core`）。纯新增，API 快照已同步。
- **测试入口守卫（T6）**：`npm test`（`scripts/test.mjs`）在不满足 `engines`（Node ≥ 22.19.0）时直接失败，并兜底判定「实际跑过的用例数 > 0」，杜绝「一个测试没跑、退出码仍为 0」的假绿。
- **依赖一致性断言（T7）**：`verify:local` / `pack` 增加「`node_modules` 关键依赖实际版本匹配 `package.json`」的前置检查，依赖装错会在门禁层被拦住而非伪装成测试失败。
- **基准环境指纹（D5）**：`snapshots/bench-baseline.json` 顶层新增 `fingerprint`（platform/arch/node/cpuModel），跨机比较直接拒绝；吞吐判定改为「同机相对基线」，绝对值只报告。

## 修复

- **T2**：`C15` 不变量与 `removeMember`/`setCaps`/`leave` 的管理员护栏统一盯 `setCaps`（此前护栏护 `setCaps`、断言盯 `dissolve`，会漏报「移走最后一个 `setCaps` 持有者」）。
- **T3**：静音消息落到冷流时由「parked（`ENDPOINT_GONE`）」改为「只写 Inbox、delivery 留在 queued」，不再 park 也不丢正文，与 C01 的「静音不唤醒」对齐。
- **T8/T9**：规范就地标注两处语义边界——`outboxDoneRetentionMs` 保留窗口起算点是 `claimed_at` 而非精确 `done_at`；`abandoned` 的「发起方账号注销」分支当前无触发路径。

## 升级步骤

1. `node -v` 确认 ≥ 22.19.0（`npm test` 自带守卫，不满足会直接红）。
2. `npm install` 后 `npm run build`。
3. 若代码里 `import type { MeshEvent / MeshEventMeta }`：按上表迁移为事件名载荷类型。
4. 校验：`npm run check:imports && npm run typecheck && npm test && node scripts/gen-snapshots.mjs --check`。

## 回滚方式

无数据迁移。破坏性变更仅是移除两个**从未被构造**的公共类型，回退到带 `MeshEvent`/`MeshEventMeta` 的旧 tarball 即可恢复它们（但规范已随 1.0.2 移除，回退需同步回退规范）。其余为纯新增导出与门禁增强，旧调用不受影响。
