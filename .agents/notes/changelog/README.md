# notes/changelog — 变更文档

## 收录什么

- 版本发布说明：本次发布包含什么、影响谁
- 破坏性变更与升级指引：调用方需要改什么
- 数据迁移 / 配置变更步骤及回滚方式
- 线上问题修复的对外说明

## 不收录什么

- git log 能直接看到的逐条 commit（这里写**对使用方的影响**）
- 内部实现细节 → `notes/tech/`

## 命名

按版本或日期命名：`YYYY-MM-DD-v<版本号>.md`，如 `2026-09-14-v1.4.0.md`。
若项目已有根目录 `CHANGELOG.md`，此处只放需要展开说明的单次变更（迁移指引、破坏性变更详解），不重复维护两份列表。

## 模板

```markdown
---
title: v<版本号> 变更说明
date: <YYYY-MM-DD>
status: done
owner: <发布人>
tags: [release]
related: []
---

## 概要

<这次发布最重要的一两件事。>

## 破坏性变更

| 变更 | 影响范围 | 迁移方式 |
| --- | --- | --- |

## 新增

- <功能及使用方式>

## 修复

- <问题现象 → 修复结果>

## 升级步骤

1. <按顺序给出可执行步骤，含配置项与数据迁移命令>

<出问题时如何退回，以及不可逆的部分。>
```
