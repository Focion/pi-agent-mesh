## D 类：待决策（需要定夺方向）

| ID | 事项 | 冲突点 | 可选方向 |
| --- | --- | --- | --- |
| **D1** | **事件的 `endpointId` 没有全覆盖** | 规范 §12.5 写的是硬要求「每个事件都携带 `endpointId`，未显式写出该字段的由库在派发时补上」。实现只给了 6 个（`message_delivered` / `message_consumed` / `message_parked` / `message_dropped` / `message_acked` / `endpoint_state_changed`），其余 9 个（`message_routed`、`inbox_overflowed`、`conversation_changed`、`membership_caps_changed`、`shared_object_changed`、`presence_changed`、`request_timeout`、`policy_degraded`、`invariant_violated`）没有该字段 | ① 补实现：9 个事件载荷各加 `endpointId?`，由发生地 / 操作方端点填充（公共面成员级扩展，不破坏订阅者）；② 收窄规范：把"每个事件都带"改成"带端点语义的事件才带"，并说明排障时如何定位。**不选就是让规范里挂着一条不成立的硬要求** |
| **D2** | **`MeshEvent` 判别联合从未被构造** | §12.6 ⑤ 写「二者是同一组载荷的两种形态，实现里由映射类型生成，**不允许各自维护一份**」。实现导出了 `MeshEvent` / `MeshEventMeta`（含 `at` / `endpointId`），但事件总线只派发 `MeshEvents[K]`，判别联合没有任何生产路径——它是一个会过编译、运行时永不出现的公共类型 | ① 补一个 `on("*")` 或 `toMeshEvent()` 的派发面，让需要穷尽 `switch` 的订阅者真能拿到；② 从公共面移除这两个类型（破坏性，要进 CHANGELOG）。与 D1 同源，建议一起定 |
| **D3** | **`wake_per_message_busy` 没有自增点** | 附录 E 把它列为 7 个派生指标分子之一、目标值 0。W14 以"它是恒 0 的 canary"为由移除了唯一的 bump 点，于是"忙时错误地另起轮次"这件事**永远不会被计数发现** | ① 恢复 bump，但只在**真的另起了一轮**时 +1（不是在正确合并时 +1）；② 保留现状并在附录 E 写明它是一个"没有探针的指标"，同时给出替代判据（例如从 `message_delivered{woke:true}` + 当时 `busy` 推导） |
| **D4** | **多 profile 与 `Account.profileRef` 未实现** | LD6 已冻结为"按 `Account.profileRef` 选 profile，无引用用 default"，W00-L6 只落了配置指纹，profile 解析留作"后续方案"。现状：`Profile` 类型已导出，`profiles` 配置项不存在，`profileRef` 只存不读；"恢复期模型变更"的规则也只在设计文档里写了默认值，没有实现 | ① 本轮实现（`CreateMeshOptions.profiles` + 解析 + profile 间不串工具 / 模型的测试）；② 明确降级为非目标，并把 `Profile` 类型从公共面移除或标注"预留" |
| **D5** | **G06 的判定口径是机器绑定的，跨机不可复现** | W15 要求 G01–G07「可重复、可机器判定」。但 `snapshots/bench-baseline.json` 只有三个数字、没有机器 / Node / 负载指纹，§8.1 的「≥200 任务/秒」也是绝对值。本次在 Linux x64 容器上实测：正确性断言每轮全过，`a-dual` 时间 +277%、`c-queue` 时间 +132% 且吞吐约 165/s，G06 直接判失败。**这不构成代码退化的证据，也不构成没有退化的证据** | ① 基线带环境指纹，换机即要求 `--record` 重录并拒绝跨指纹比较；② 把绝对吞吐阈值改成"同机相对基线"，绝对值只报告；③ 承认 G06 只在 §8.2 的参考机上有效，并在门禁输出里写明 |
| **D6** | **demo 已超出 LD8 / D07 的范围，且没有自动化回归** | LD8 冻结为「demo 只改读 Mesh 配置，不扩展 UI、不恢复旧五页」，D07 写明「不恢复旧五页 demo」。`615c1f0` 把 demo 扩成 5 Tab 能力面板，发生在计划 `status: done` 之后，没有对应的决策记录。当前 demo 只有 `typecheck:demo` 一道类型门禁，前端是 vanilla JS、不在任何门禁内 | ① 追认这次扩展并给 demo 定一条可执行的回归口径（至少：启动 + `/api/health` + 每个 Tab 的一条冒烟）；② 把 demo 收回 LD8 的范围。**在决定之前，改 demo 仍必须手工启动服务并在浏览器里验证受影响的 Tab** |

## T 类：待办（方向明确，只差做）

| ID | 事项 | 来源 | 闭合条件 |
| --- | --- | --- | --- |
| **T1** | P2 路径的 queue 投递不开 `claim_until` | W10 关闭记录里的「发现的既有问题」 | 超预算落 P2 的 queue 任务经 `confirmInjection` 转 `delivered` 时也开待领窗口，`reclaimExpiredClaims` 能回收它；补一条多消费者 + 超预算的契约测试 |
| **T2** | `§12.2` 的管理员护栏与 `C15` 断言盯的不是同一个能力位 | W04 偏差② | `removeMember` / `setCaps` / `leave` 护住的是最后一个 **`setCaps`** 持有者，`C15` 断言的却是群里至少有一个 **`dissolve`** 持有者（附录 D 的 `NO_ADMIN_LEFT` 两个都写了）。结果是"移走最后一个 `dissolve` 持有者"能通过护栏却会让 `C15` 报违反。统一到一个位上，两处同时改 |
| **T3** | `§9.5:1724` 与静音语义的张力 | W06 偏差② | §9.5:1724 说「`!wake && !verbatim` 才只写 Inbox」，而 C01 把静音消息强制 `silent` 之后，预算内（= verbatim）的静音消息在冷流上会走 `silent + cold ⇒ parked`。确定 `silent` 冷流守卫要不要补 `&& !verbatim`，然后对齐 §9.5 与实现 |
| **T4** | 多消费者 queue 的 `exclusive` 与换人重投 | W10 偏差①② | §17.3 的 claim 期 `exclusive` 租约、§17.4 的"回队换一个消费者 + affinity 排除上次失败端点"都还没实现（单消费者下等价）。随 pooled 拓扑一起收口，并补 8 消费者的竞态用例 |
| **T5** | 根入口没有再导出原因码 / 计数器名 / 工具名常量 | 本次复核 | `REJECT_CODES` / `PARK_REASONS` / `DROP_REASONS` / `TOOL_ERROR_CODES` / `REGISTERED_COUNTERS` / `MESH_TOOL_NAMES` 只在 `@pi/agent-mesh/core` 上；包根只导出了 `MESH_ERROR_CODES` 与 `DEFAULT_LIMITS`。§12 把"原因码常量与计数器名"算进公共面，而公共面的判据是"从包根导出"——两边对不上。补根 re-export（纯新增）并重生成 API 快照 |
| **T6** | `npm test` 在不满足 `engines` 的 Node 上**静默返回 0** | 本次复核实测 | 本机默认 Node 20.18.0 下 `npm test` 的 vitest fork 池直接 `ERR_IPC_CHANNEL_CLOSED`，**一个测试都没跑，退出码仍是 0**。`scripts/pack.mjs` / `verify-local.mjs` 有 Node 守卫，`npm test` 没有。给测试入口加同样的 Node 守卫；再考虑加一条"实际跑过的用例数 > 0"的兜底判定 |
| **T7** | 没有"`node_modules` 与 `package-lock` 一致"的前置检查 | 本次复核实测 | 复核开始时 `node_modules` 里是 pi **0.85.1**，而 `package.json` / `package-lock.json` 要的是 `^1.1.0`；12 个 `tests/pi` 用例因此失败，看起来像代码缺陷。`npm install` 之后全绿。给 `verify:local` / `pack` 加一条关键依赖实际版本的断言 |
| **T8** | outbox 保留窗口用 `claimed_at` 近似 `done_at` | W07 偏差③ | 要精确"done 之后整 24h"就得加 `done_at` 列（新迁移）。先判断排障是否需要这个精度，不需要就把近似写进附录 F.1 的说明 |
| **T9** | `§14.4` 的"发起方账号注销 ⇒ abandoned"没有接线 | W09 剩余风险① | 本版没有 `deregisterAccount` API，该分支无从触发。等该 API 落地时同批接上；在那之前规范里这一条应标注为"无触发路径" |
