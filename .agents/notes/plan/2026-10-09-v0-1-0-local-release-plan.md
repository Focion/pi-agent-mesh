## 1. 目标、状态与授权边界

目标是形成 **`@pi/agent-mesh@0.1.0` 当前能力稳定版的本地可安装 tarball**，而非宣称实现完整1.0规范或已经公开发布。

**包版本保持0.1.0，不升版、不增加预发布后缀。** `package.json`、`package-lock.json`中的本包版本及`LIBRARY_VERSION`保持现值；原基线与修复后候选以源码快照和tarball SHA-256区分，不覆盖已有同名产物。数据库结构迁移仍按实际DDL差异验证，不能因包版本相同就推断数据库或行为完全兼容。

用户已确认：

1. 以当前能力稳定版为目标，修复gap中的40项实现/接线差距，补足本地验证，并将D03恢复正确性纳入本版。
2. 采用本文C01–C10决策；定向历史隔离及未来扩展继续延期。
3. 只要求本地包就绪；升级基线为当前仓内0.1.0合成数据库及示例，不是未提供的历史真实发布库。
4. **本次只创建计划，不实施、不运行测试、不安装依赖、不修改源码/配置/历史文档，不提交、不打tag、不上传、不发布。** 决策确认不等于实施授权。

当前完成的是合同与任务规划。所有W工作包均为`todo`，所有G门槛均为`not_run`；只有将来获实施授权且门槛通过，才能称“本地包就绪”。本计划`status: draft`表示尚未执行，不表示C类决策仍悬而未决。

将来交付应同时具有：

- 版本一致、不可变校验值对应的0.1.0 tarball；干净消费者离线安装后可运行。

### 2.1 九槽失败及边界合同

| 策略槽 | 失败/非法结果处理 | 必须验证的边界 |
| --- | --- | --- |
| delivery | `silent`且no-wake，保留允许的账本/Inbox | 不让direct、urgent或下游覆盖失败结果 |
| activation | false | 正常策略下合法direct/request仍应起轮；失败场景不得混进正常性能分母 |
| floor | 原有free_for_all回退，但候选须已合法且具speak权限 | 不授予非成员/无权者；不等同ACL放行 |
| renderer | 内建包裹与转义；自定义不合规输出拒绝或修壳并告警 | 壳前/壳后裸文本、嵌套定界符、系统与P2内容同验 |
| clock | 内建compare/format，记录降级 | 只负责约定的逻辑时间比较/显示；**不取代权威seq或变成新增wall-clock定时器策略** |
| accessControl | deny；custom无人判定也deny | canRead/write/admin/send/publish/join/首聊等统一包装，禁止重入写操作 |
| retention | 原文bytes=0；保留允许的摘要/游标 | 不以默认原文预算掩盖策略失败 |
| endpointSelector | park并记录原因 | 数组全部校验账号归属，不取首项冒充完整结果 |
| sessionFactory | 独立秒级deadline；失败为NO_SESSION并告警 | 不能用毫秒级普通策略超时；迟到结果不附着，调用dispose收尾；dispose失败仍记录阻塞，不能释放仍有写者的锁 |

普通异步策略沿既有`policyTimeoutMs`；SessionFactory拟采用独立可配置超时，默认30秒，此值是本版设计值而非SDK保证。同步宿主代码不能被同线程timer安全中断：只在返回后测时/验值/异常降级。测试恶意无限循环只能放入可终止的**本次测试子进程**；不为此引入生产worker隔离系统。异步deadline只限制等待，不自动取消宿主副作用，须有代次防止迟到结果污染状态。

### 2.2 安全与数据合同补充

- Shared put先按旧ACL检查write，修改ACL和删除需要旧ACL的admin；新建按新建合同。事务前异步授权后，在事务内重验版本与授权依据，不能跨await沿用过期权限。
- 私有Shared变更**不能仅靠group消息的to字段保护**，因为D07定向历史仍延期。最小方案：只有全部潜在历史可读成员均有对象read权限时才写公共会话通知；否则抑制该best-effort群通知，保留宿主事件。允许发送的Shared通知固定silent/no-wake，不能触发额外起轮。不另造不可靠的私密消息通道，不泄露对象key。
- shared get历史version入参保持有效；工具成功结果保留既有data字段，并增加必要version元信息；put/list声明参数实际生效。底层reject/null保持D05，不新增getRaw或强制恢复联合类型。
- seal默认关闭；启用由宿主提供内存密钥，不持久化密钥。启用模式拒绝未签/验签失败的待投递消息，不能给旧历史重新签名冒充可信；已有未签历史仍可只读查询。签名规范化字段和升级限制进入W03验收。
- P1可靠性界定为持久意图＋至少一次搬运＋单写者保护下可核对的幂等应用；不得承诺任意SinkHandler副作用、任意宿主扩展的无条件exactly-once。

### 6.3 基准口径与防止伪通过

依据规范§24.4，固定输入/环境/计量范围，先跑朴素正确基线，再测候选；不能以性能目标推动状态机投机优化。

- **A：双Agent、200条既定交替direct消息**。逐步oracle确认合法请求/应答应起轮与原文均未遗漏，hot=2、无折叠；不能为压低唤醒取消合法请求。区分主动输入、自动响应和协议消息，分母由夹具定义并随结果保存。
- **B：30成员、500条固定seed消息，5%请求定向1–2人**。唤醒≤600，原文份数≤1500，hot峰值≤4，静默率>0.5、原文率<0.25；busy新增起轮=0。delivery数由实际收件集合oracle求和，**不把规范近似14500硬写成精确值**，否则与定向请求集合矛盾。
- **C：8消费者、1000任务，无故障基准**。每任务恰好一个成功ack终态，claim冲突率≤15%，claim超时回收=0，dedup_hit=0，纯账本吞吐≥200任务/秒（不含业务处理时间）。故障套件允许协议重试产生dedup，不混入该无故障门槛。
- idle平均唤醒≤1.2、原文≤3按适用场景核对；群聊静默率/原文率不能机械施加到A的合法高频请求场景。各场景结果分列，不能混合平均。
- 性能预热3轮、测量5轮，保存全部样本、中位数和p95；**正确性、事件计数、比例、hot峰值及预算硬门槛每轮均须满足；吞吐≥200任务/秒与相对20%不利退化按5轮中位数判定，p95仅报告、不作为隐含门槛。** p95按5个有序样本的nearest-rank（第5个）计算，并注明样本数；不将其作为充分的尾延迟估计。只对越出明确上界/下界的不利方向判断回归，不把更低的合法唤醒盲视为优化。绝对硬门槛先通过，同输入同环境的候选相对已冻结正确性基线不利退化>20%仍阻塞。旧实现不满足合同的指标不能作为“正常基线”，须明确记录后建立正确基线再测。
- hot峰值受场景会话时序影响，测试夹具须明确冷/热起点和请求并发；不能靠预热全体成员、手动将任务离线或直接插终态行绕过实际路径。
