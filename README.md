  - 门禁修复 A40、A42、A44 须在迁移步骤 3 之前完成。

共用时间线：环境 → 门禁与快修 → 迁移阶段一 与 审计 core 修复并行 → 迁移阶段二 → 复查与归档。详见审计计划「执行时机与职责划分」一节和迁移计划 §10。

## 使用方式

在仓库根目录解压，按包内路径覆盖：

```bash
unzip -o pi-agent-mesh-plans-20261020.zip -d /tmp/plans
cp -r /tmp/plans/pi-agent-mesh-plans-20261020/.agents/. <repo>/.agents/
```

如果只想合入 `.agents/AGENTS.md` 的改动，可以在仓库根目录执行 `git apply AGENTS.md.patch`。前提是该文件仍处于基线提交 `c9567a8` 的状态。

## 已知限制

- 审计期间本机默认 Node 是 v20.18，低于 engines 要求的 ≥22.19；`node_modules` 中的 pi 版本（0.85.1）也与 lock（1.1.0）不符。用 Node 22.16 跑全量测试，有 12 条失败，全部在 `tests/pi`，根因是环境而非代码。覆盖率门禁没有跑过。
- 审计结论分「确认」和「可能」两档：「确认」是脚本复现过或读码走通了触发链，「可能」只读过代码。「可能」级条目要先写复现测试再修。
